Azure 学生优惠自建节点教程：从申请订阅到全平台可用

发布于 2026/10/25

一台自己的 VPS，一个自己的节点，全设备可用，不与他人共享带宽。

本教程记录我从零开始的全过程：申请 Azure 学生订阅 → 创建日本 VPS → 安装 3x-ui 面板 → 配置 VLESS+Reality → 四个平台的客户端接入。文末附 4 个真实踩坑记录，都是亲手撞过并修好的。

本教程用到的入口：

🔗 Azure 学生优惠：https://azure.microsoft.com/zh-cn/free/students

🔗 3x-ui 面板（GitHub）：https://github.com/MHSanaei/3x-ui

🔗 v2rayN（Windows 客户端）：https://github.com/2dust/v2rayN

🔗 v2rayNG（Android 客户端）：https://github.com/2dust/v2rayNG

一、方案总览

组件 选择 理由
VPS Azure 虚拟机，日本东部，B1s 规格 学生订阅额度覆盖；日本离得近、延迟低
管理面板 3x-ui 开源、中文界面、自带订阅和分享链接
节点协议 VLESS + TCP + Reality 无需域名和证书；伪装成正常 HTTPS 流量
客户端 Xray 内核系（v2rayN / V2Box / Streisand / v2rayNG） 兼容性最好；Clash 系内核连不上，见踩坑实录

一个重要提醒放在最前面：这个方案的客户端只能选 Xray 内核系，不要用任何 Clash 系客户端（Clash Verge、ClashX、FlClash、Stash 等）。原因是 mihomo（Clash 系内核）目前无法完成新版 Xray 的 Reality 认证，官方明确不修（mihomo issue #2967、#2998）。我在这上面耗了一整个下午，详见踩坑实录。

二、申请 Azure 学生优惠

Azure for Students 面向高校学生提供 12 个月免费额度（具体金额与条款以官方页面实时显示为准），不需要信用卡，用学校邮箱完成学生认证即可。

  1. 打开 🔗 https://azure.microsoft.com/zh-cn/free/students ，点「免费开始使用」；
  2. 用微软账号登录（没有就现场注册一个）；
  3. 按页面引导完成学生身份验证——一般通过学校邮箱或学籍信息核验，由 SheerID 提供验证服务；
  4. 验证通过后订阅即生效，登录 Azure 门户 就能看到自己的订阅。

认证不通过的常见处理：换浏览器或清除 Cookie 重试；确认学校邮箱拼写正确；确认学校在验证服务覆盖范围内。以 Azure 页面提示为准，这里不展开。

三、创建 VPS

1. 创建虚拟机

登录 portal.azure.com → 搜索「虚拟机」→「创建」→「虚拟机」，按这个表填：

配置项 填什么 说明
区域 Japan East 离国内近，延迟低
镜像 Ubuntu Server 24.04 LTS 3x-ui 对 Ubuntu 支持最好
大小 B1s（1 vCPU / 1 GiB 内存） 跑代理绰绰有余，额度消耗小
管理员账号 SSH 密钥或密码均可 记住用户名（默认 azureuser）
入站端口 允许 SSH (22) 其余端口后面手动加

点「查看 + 创建」→「创建」，等一两分钟虚拟机就绪，在概述页记下公网 IP 地址。

2. 放行端口（NSG 网络安全组）

Azure 的虚拟机默认只开了 22 端口，别的端口一律静默丢包（表现为连接超时），必须手动放行：

  1. 门户左侧「虚拟机」→ 选中你的虚拟机 →「网络设置」；
  2. 点「添加入站端口规则」，一条规则可以写多个端口：目标端口范围填 2233,443（2233 给面板用，443 给节点用），协议 TCP，操作「允许」，优先级 310，名称随意（如 Allow_Proxy）；
  3. 保存即生效，不用重启虚拟机。

注意从这里进（虚拟机 → 网络设置），而不是直接搜「网络安全组」进去——NSG 有网卡和子网两层，从虚拟机页面进去会自动改对地方。

四、安装 3x-ui 面板

1. SSH 登录

Windows 10/11 自带 ssh，直接在终端里执行：

ssh azureuser@你的公网IP

2. 一键安装脚本

bash <(curl -Ls https://raw.githubusercontent.com/MHSanaei/3x-ui/master/install.sh)

安装过程中会依次让你设置：用户名、密码、面板端口（建议 2233），并自动生成一个随机的网页访问路径。全部记下来——面板地址形如 http://你的IP:2233/随机路径/。

3. 登录面板

浏览器打开面板地址，用刚设置的用户名密码登录。能看到中文界面就说明面板装好了。

安全提醒：面板是纯 HTTP 明文传输，密码和节点信息不要在不可信网络下登录查看；面板地址和密码等同于服务器的钥匙，不要发给任何人、不要发到公开场合。

五、配置节点（VLESS + Reality）

1. 添加入站

面板 →「入站列表」→「+ 添加入站」，关键项按这个表填，其余保持默认：

配置项 填什么
备注 随意，如 Japan-443
协议 vless
端口 443
传输 tcp
安全 reality
目标(SNI) www.microsoft.com:443

Reality 的密钥对面板会自动生成，不需要域名和证书。端口务必用 443：Reality 伪装成正常 HTTPS 流量，跑在 443 上最合理，也最不容易被针对（我在 8080 上跑了一天就被墙了端口，见踩坑实录）。

2. 两个必改的隐藏参数（重点）

在入站编辑页点「高级配置」→「全部」子标签，在 JSON 里搜到并修改这两项：

"minClientVer": "1.8.2",
"maxTimediff": 60000,
  • minClientVer：Xray 26.7.11 起默认拒绝低于 26.3.27 的客户端，很多客户端会被莫名拒之门外，显式写上就恢复兼容；
  • maxTimediff：26.10.x 把 0 处理成零时钟容忍，服务器和你的电脑时钟差几秒就会连接失败，改成 60000（允许 60 秒偏差）一劳永逸。

改完点保存；如果首页 Xray 状态没有自动重启，手动点一下「重启 Xray」。

3. 复制分享链接

入站列表 → 该入站的客户端 → 点分享/二维码图标，复制形如 vless://... 的链接。所有设备都用这一条链接。

六、四个平台的客户端

平台 推荐 App 获取方式 费用
Windows v2rayN GitHub Releases 下载 免费
macOS V2Box App Store 免费
iOS Streisand 或 V2Box App Store 免费
Android v2rayNG GitHub Releases 下载 APK 免费

共同操作：把 vless:// 链接传到设备上（微信文件传输助手 / AirDrop / 备忘录同步）→ 客户端里「从剪贴板导入」→ 选中节点 → 开启系统代理或 VPN 开关。

Windows（v2rayN）：下载解压后运行 v2rayN.exe → 主界面 Ctrl+V 导入 → 选中节点测延迟 → 左下角「路由」选「绕过大陆」→「系统代理」选「自动配置系统代理」。

macOS / iOS（V2Box / Streisand）：App Store 安装（国区搜不到就换外区 Apple ID）→ 复制链接后在 App 里从剪贴板导入 → 选中节点启动 → 路由分流里选绕过大陆的预设。

Android（v2rayNG）：GitHub 下载 APK 安装 → 复制链接后在 App 里从剪贴板导入 → 选中节点 → 底部开关启动 → 路由选「绕过大陆」。

七、踩坑实录（每条都真实修好过）

  1. 非 443 端口跑 Reality，一天后被墙。症状是该端口连接全部超时、同 IP 其他端口正常。GFW 会针对「IP:端口」选择性封锁，非标准端口上反复的异常握手极易触发。解法：节点放 443。
  2. Clash 系客户端全部连不上。无论什么版本、什么指纹，Reality 认证都被拒。这是 mihomo 与新版 Xray 的已知不兼容，官方 wontfix。解法：换 Xray 内核客户端。
  3. 节点参数全对却认证失败。Xray 26.7.11+ 默认拒绝低版本客户端。解法：入站里显式设置 minClientVer。
  4. 本地测试通过、远程连不上。新版 Xray 把 maxTimediff: 0 处理成零时钟容忍，服务器与本地时钟差几秒就失败。解法：改成 60000。

八、日常维护

  • 流量与状态：面板首页能看到每个客户端的流量和在线状态；Azure 门户「成本管理」里看额度消耗。
  • 更新 Xray：面板「Xray 更新」入口可以升降级内核版本；升级后如果节点异常，对照第五节的两个隐藏参数检查一遍入站配置。
  • 备份：面板设置里有数据库备份，定期导出一份。
  • 订阅服务（可选）：面板设置 →「订阅」里启用后（默认端口 2090，记得在 NSG 放行），每个客户端会有一条订阅链接，多设备填订阅链接可以自动同步参数。

九、常见问题

浏览器报 ERR_PROXY_CONNECTION_FAILED？ 客户端的内核没跑起来，多半是没有选中节点。先在客户端列表里单击选中节点（高亮），再开系统代理。

能上国内网站、国外打不开？ 路由没有选「绕过大陆」预设；或者同时开了两个代理软件互相打架——只保留一个。

客户端测延迟一直 Timeout？ 按顺序检查：Azure NSG 是否放行了 443 → 客户端参数是否和分享链接一致（尤其端口）→ 入站里 minClientVer 和 maxTimediff 是否按第五节设置。

学生认证一直不通过？ 确认学校邮箱可用、学校在覆盖范围内，换浏览器重试；具体以 Azure 页面提示为准。

最后一句：节点链接和面板密码是服务器的全部钥匙，仅供自用，妥善保管，遵守所在地法律法规。
